**Two lessons from today, for whoever merges next:**

- `gh pr merge` needs the full 40-character SHA for `--match-head-commit`; the short form fails
  after the command has already been chosen. Do not chain a branch deletion after a merge without
  checking the merge succeeded: a failed merge followed by `git branch -D` and `git push --delete`
  closed #739, which had to be reopened from the local branch.
- A branch that predates a merge into `main` may still pass its own checks and then fail on the
  hosted runners, because the fixes it needs landed later. Merge `main` in before the final CI run.

## 1. The rules (these override your defaults)

1. **Work in a worktree, never in the shared checkout.**
   `git -C /mnt/d/Projects/MegaPDF worktree add .claude/worktrees/<n>-<slug> -b wip/<n>-<slug> origin/main`.
   Your Edit/Write tools are local-only; for a remote build, author locally and sync to a clone.
   Remove the worktree and both branches after the merge.
2. **Local machines first; hosted CI is the merge gate, not the proof.** GPD-DAVE (this machine) for
   WinUI; the Mac mini (`ssh mac-mini`, recipe in `tools/mac-mini.md`) for macOS and iOS; kdocker3 for
   Linux, .NET and corpus work; kdocker2 for Android (`/data/megapdf-work/<n>`, `GRADLE_USER_HOME`
   there too). Name your simulators `megapdf-agent-<n>`, never `megapdf-ci-*` (CI deletes those).
3. **Never end a turn waiting on a job.** Poll in the foreground with sleeps until it settles.
4. **Secrets:** never print one, never put one in argv, never render a process table or environment
   dump. The secrets hook blocks some prose words in shell commands; write bodies with the Write
   tool and pass `--body-file`.
5. **Windows UI runs are serialised:** take `mkdir /mnt/d/megapdf-qa/winui-lock` before launching
   MegaPDF on GPD-DAVE, release it after (also on failure). Automation launches use an isolated data
   folder since #717/#721; QA scripts start with `Start-QaUserDataWatch` and never remove a package
   they did not install (`tools/windows-qa/qa-safety.ps1`). The WSL session is elevated and an
   elevated WinUI app gets no file picker: picker checks launch at normal rights.
6. **Leave every machine as found.** No clones, simulators, containers, packages, scratch or windows.
7. **Platform-native conventions are a rule.** The design comments name the idiom; use it.
8. **Strings:** three locales today, four with #724. fr-CA hand-written, fr-FR derived by
   `tools/gen_strings.py fr-fr`; es-419 hand-written, es-ES derived (#724). Every new French string
   `FR-REVIEW #<issue>`, every Spanish one `ES-REVIEW #724`, in the platform's idiom (XML comment on
   Android, the `comment` field on iOS, never `stringUnit.state`). Check
   `docs/localisation-glossary.md` first; add rows. **Fable's approval gates the French and the
   Spanish**; nothing with an unreviewed marker ships.
9. **Tests:** every test file cited in `tests/matrix/coverage.toml`
   (`python3 tools/qa/check-matrix.py --check`); a new Windows self-test state gets a `Run-Check`
   line in `ci.yml` and must have run locally first. Prove each new test fails without its change.
10. **The bar is "code complete, lightly tested"** (Dave, 2026-10-20): the new tests and the existing
    suites for what you touched, green locally, then PR CI green on the head SHA. Corpus batteries
    and store captures are release gates, not per-PR work, except where a design says otherwise.
11. **PR to `main`; the coordinator merges.** Verify a run is a `pull_request` event on the PR's
    current head SHA before trusting it ("no checks reported" is a red flag). Merge `main` into the
    branch when it has moved; regenerate `docs/qa/test-matrix.md` on conflict. Delete the branch
    after the merge.
12. **Milestones are Dave's.** Never create, close or move one. Deferred work is filed unmilestoned.
13. **Record decisions on the issue**, timestamped, and close finished issues with a comment written
    for someone reading in six months: what was verified, where, what remains.
14. **Report honestly.** Say what was verified and how, what was not, and when the issue's theory was
    wrong. The designs already found the theory wrong on most issues; expect more.
15. **Commits and PRs** end with the attribution lines the session gives you.
16. **Tidy as you go:** `tools/release-readiness.sh` lists what stands between the repo and a release;
    keep it clear (merged branches deleted, worktrees pruned, `main` green, docs naming the version).

## 5. How to run this

- Act as the coordinator: one agent per item, briefs that quote the design comment and the rules
  above, the "code complete, lightly tested" bar, PR-but-do-not-merge. Review each PR against its
  design before merging. Keep `main` green; a red `main` is the first thing to fix.
- Keep the handoff current: a memory note per session with what landed, what is in flight, and
  what bit, so the next agent resumes without re-reading everything.
- When all three waves are done, run RELEASING.md and hand Dave the release summary the way 2.3.0's
  #696 did: live where, in review where, what was not verified.
