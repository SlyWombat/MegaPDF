### Lessons, for whoever merges next

- `gh pr merge` needs the full 40-character SHA for `--match-head-commit`. Never chain a branch deletion
  after a merge without checking the merge succeeded: a failed merge followed by `git branch -D` closed
  #739 by mistake.
- A branch that predates a merge into `main` may pass its own checks and then fail on the hosted runners.
  Merge `main` in before the final CI run, and **read why a check failed** before assuming the branch's
  own code: #755's red was Spanish parity, landed by another PR.
- A merge does not close an issue unless its PR body says so. #644 sat open after #740 merged until its
  closing comment was written. Check each merged issue's state at the time of the merge.
- iOS CI now queues behind the Mac mini's one slot (median 17 min on a busy day). Do not read a long
  `queued` as a hang; do not dispatch hosted runs to "speed it up" except for #614's measurement.
- An issue's theory was wrong on most issues this milestone (#640 untouchable tile, #633 flatten gate,
  #635 "no PHP", #660 "nothing wrong", #593 fixture sizes). Measure first; say so in the PR.

## 1. The rules (these override your defaults)

1. **Work in a worktree, never in the shared checkout.**
   `git -C /mnt/d/Projects/MegaPDF worktree add .claude/worktrees/<n>-<slug> -b wip/<n>-<slug> origin/main`.
   Your Edit/Write tools are local-only; for a remote build, author locally and sync to a clone.
   Remove the worktree and both branches after the merge.
2. **Local machines first; hosted CI is the merge gate, not the proof.** GPD-DAVE (this machine) for
   WinUI; the Mac mini (`ssh mac-mini`, recipe in `tools/mac-mini.md`) for macOS and iOS; kdocker3 for
   Linux, .NET and corpus work; kdocker2 for Android (`/data/megapdf-work/<n>`, `GRADLE_USER_HOME`
   there too). Name your simulators `megapdf-agent-<n>`, never `megapdf-ci-*` (the standing runner
   deletes those at every job start). Take `mkdir ~/.megapdf-sim.lock` on the mini before a simulator
   run and remove it after; two agents' simulator runs on the mini at once have stalled both.
3. **Never end a turn waiting on a job.** Poll in the foreground with sleeps until it settles.
4. **Secrets:** never print one, never put one in argv, never render a process table or environment
   dump. The secrets hook blocks some prose words in shell commands; write bodies with the Write
   tool and pass `--body-file`.
5. **Windows UI runs are serialised:** take `mkdir /mnt/d/megapdf-qa/winui-lock` before launching
   MegaPDF on GPD-DAVE, release it after (also on failure). Automation launches use an isolated data
   folder since #717/#721; a person's launch (real-input checks) sets `MEGAPDF_USER_DATA` to a scratch
   folder first. QA scripts start with `Start-QaUserDataWatch` and never remove a package they did not
   install (`tools/windows-qa/qa-safety.ps1`). The WSL session is elevated and an elevated WinUI app gets
   no file picker: picker checks launch at normal rights.
6. **Leave every machine as found.** No clones, simulators, containers, packages, scratch or windows.
   The clipboard belongs to the machine's owner: save and restore it; stop if it holds non-text.
7. **Platform-native conventions are a rule.** The design comments name the idiom; use it.
8. **Strings: five locales.** fr-CA and es-419 hand-written; fr-FR and es-ES derived by
   `tools/gen_strings.py fr-fr es-es`, never hand-edited. Every new French string `FR-REVIEW #<issue>`,
   every new Spanish string `ES-REVIEW #<issue>`, in the platform's idiom (XML comment on Android, the
   `comment` field on iOS, never `stringUnit.state`; on iOS both markers share one `comment`). Add rows
   to `docs/localisation-glossary.md` **and** `docs/localisation-glossary-es.md`; a glossary conflict
   keeps both sides' rows. Canada: U+00A0 before `:` only, France derives the rest; Spanish: no space
   before anything, `¿ ¡`. **Fable's approval gates both languages**; markers stay in the files after
   approval (the record is the issue comment and the release notes, as #694 did), so "unreviewed" means
   "added after the last approval comment", not "has a marker".
9. **Tests:** every test file cited in `tests/matrix/coverage.toml`
   (`python3 tools/qa/check-matrix.py --check`); a new Windows self-test state gets a `Run-Check`
   line in `ci.yml` and must have run locally first; a new iOS UI suite goes in `ios/ui-test-lanes.txt`
   (#598). Prove each new test fails without its change.
10. **The bar is "code complete, lightly tested"** (Dave, 2026-10-20): the new tests and the existing
    suites for what you touched, green locally, then PR CI green on the head SHA. Corpus batteries
    and store captures are release gates, not per-PR work, except where a design says otherwise.
11. **PR to `main`; the coordinator merges.** Verify a run is a `pull_request` event on the PR's
    current head SHA before trusting it ("no checks reported" is a red flag). Merge `main` into the
    branch when it has moved; regenerate `docs/qa/test-matrix.md` on conflict. Delete the branch
    after the merge.
12. **Milestones are Dave's.** Never create, close or move one. Deferred work is filed unmilestoned.
13. **Record decisions on the issue**, timestamped, and close finished issues with a comment written
    for someone reading in six months: what was verified, where, what remains.
14. **Report honestly.** Say what was verified and how, what was not, and when the issue's theory was
    wrong.
15. **Commits and PRs** end with the attribution lines the session gives you.
16. **Tidy as you go:** `tools/release-readiness.sh` lists what stands between the repo and a release;
    keep it clear (merged branches deleted, worktrees pruned, `main` green, docs naming the version).
